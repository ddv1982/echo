# Retained compatibility boundaries

Plan 22 retains the following protocols and capabilities. No version cutoff or retirement is introduced. These records describe current support, not deployed-version usage.

| Owner and consumers | Accepted format or capability | Existing contract tests | Condition for a future change |
| --- | --- | --- | --- |
| `echo::rec` and `process_identity`; desktop and standalone CLI owners | `recording.lock` accepts a PID, a PID with token, or a PID with token and process start ticks. The current fourth line is `scoped-intents-v1`. A legacy owner must predate the token timestamp or lock mtime, and must not be a zombie. | `legacy_two_line_lock_requires_process_to_predate_token`, `live_pid_only_lock_receives_an_observable_legacy_stop_request`, `new_lock_rejects_a_reused_pid_with_a_different_start_identity` | An explicit accepted-protocol cutoff and an upgrade procedure that drains or rejects an older live owner while preserving mutual exclusion. No Echo-version cutoff is established by the source. |
| `echo::rec`; old and current shortcut commands | Current stop/cancel filenames contain the SHA-256 of the session token. Owners without the scoped marker receive flat filenames. Payloads contain the token and newline, or `stop\n` for PID-only owners. A current token owner also accepts a flat request when the token matches. | `scoped_owner_accepts_only_its_token_in_a_legacy_flat_request`, stale stop/cancel tests, `legacy_flat_capture_stop_preserves_transcription` | The same explicit protocol cutoff, a shortcut migration, and mixed-format tests proving stale or unsupported controls cannot affect a replacement session. |
| `shortcuts`; portal registration | Confirmed absence of `org.freedesktop.host.portal.Registry` still permits probing `org.freedesktop.portal.GlobalShortcuts`. Other Registry errors fail. The GlobalShortcuts interface version must be at least 1. | `only_confirmed_global_shortcuts_absence_enables_legacy_setup`, `portal_runtime_registers_binds_routes_and_closes` | An explicit Registry capability requirement, migration or failure behavior, and an adapter test for Registry absence. The existing private-bus integration test serves Registry; it does not prove the absent-Registry branch end to end. |
| `shortcuts::gnome`; compositor shortcut setup | Confirmed `PortalAbsent` on Wayland enables compositor setup. GNOME repair changes Echo's owned binding. Other compositors receive a shell-quoted absolute executable command ending in `rec --toggle`. Arbitrary portal errors do not enable repair. | `only_confirmed_global_shortcuts_absence_enables_legacy_setup`, `legacy_wayland_host_repairs_only_the_echo_owned_binding` | A stated minimum portal capability and migration or removal rules for Echo-owned bindings that preserve unrelated bindings. Desktop version examples do not establish a new minimum supported version. |
| `hotkey` and `shortcuts`; X11 installations | An X11 session uses native grabs. Wayland cannot select X11 through a stale `DISPLAY`. Unknown or headless shortcut sessions are unsupported. | `x11_runtime_registers_and_releases_the_fixed_grab`, `x11_runtime_routes_press_and_release_while_another_app_is_focused` | A product decision to change documented X11 support, plus migration and failure behavior for existing installations. Isolated grabs do not prove physical keyboard delivery. |
| `whisper_plan`, `whisper_gpu`, and `whisper_recovery`; accelerated dictation | A qualified GPU plan pairs an identified Vulkan runtime with an identified managed CPU fallback. Plan inputs and receipts must match. Eligible failure quarantines acceleration and tries CPU once within the original deadline. Cancellation or an exhausted deadline does not start fallback. | `qualified_plan_requires_exact_accelerator_and_managed_cpu_contracts`, `every_accelerator_failure_quarantines_once_and_runs_one_cpu_retry`, `fallback_inherits_the_original_global_deadline` | A product decision changing the documented recovery promise, or a proven equivalent replacement. This is active recovery behavior, not a legacy bridge with an invented expiry date. |

## Insertion decision

Keep `LinuxInjector::type_text`, `paste_text`, and `detection_summary` within the existing insertion subsystem. They do not implement one equivalent decision.

`detection_summary` reports tool presence. It advertises `ydotool` or `wtype` on Wayland, then `xdotool`, and distinguishes clipboard availability from cursor readiness. A captured X11 target permits only targeted `xdotool` typing. Untargeted command attempts can recover through other tools after an earlier command fails. Paste also requires observed clipboard transfer before it can report success.

A shared ordered backend list would need extra focus, operation, and result rules. The trace found no complete duplicated decision whose removal would simplify these paths. Existing adapter tests cover the behavior through command attempts: `typing_stops_after_each_possible_successful_backend`, `missing_focus_does_not_touch_commands_or_clipboard`, and `submitted_but_unconfirmed_targeted_paste_reports_failure`.

No generic backend registry, new fallback, or removed capability follows from this review.
