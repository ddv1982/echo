# Settings and delivery: a configurable, multilingual, shippable Echo

## Context

Echo works, and it is not yet a product. Five complaints, all fair, all traced to code during a read-only investigation of the whole repo:

**The icon is not one icon.** There are two branding files and they disagree. `assets/icons/echo.svg` is a 529-byte vector, a `#1c1c1c` rounded tile with five `#f3efe6` capsule bars and a dot. `assets/icons/echo.png` is a 1024x1024 raster in different colours (`#252628` tile, `#fcf3db` bars), stored as RGB with no alpha channel, weighing 844 KB because 23.5 KB of it is a C2PA provenance manifest naming `gpt-image` as the generator. `src-tauri/icons/icon.png` is a 256x256 downsample of that raster. Its corners are painted opaque white rather than left transparent, and it is the only entry in `bundle.icon` (`src-tauri/tauri.conf.json:33`). The tray reuses it verbatim, because `TrayIconBuilder` is handed `app.default_window_icon()` (`src-tauri/src/main.rs:255-257`) and `tray-icon` writes those pixels to a temp PNG for libappindicator to scale down. Measured on the actual pixels, the mark needs roughly 32 px to read: at 22 px the gap between bars is 0.79 device pixels, and at 16 px two of the five bars merge. So the tray shows a white-cornered square containing grey mush, the window shows the raster, the desktop entry points at a third file by a fourth name, and `frontend/index.html` has no favicon at all.

**There is no way to choose a microphone.** `AudioCapture` resolves `host.default_input_device()` and there is no enumeration anywhere in the repo. Worse, it resolves twice. `open_default` looks the device up and discards the result as a liveness probe (`crates/echo/src/audio.rs:81-82`), then `record` looks it up again (`crates/echo/src/audio.rs:89-90`). The handle does not pin a device. The original design did have one: `docs/plans/01-echo/phase-2-audio.md:19` specifies `AudioCapture` as `{ device: DeviceName, cancel: CancellationToken }`. The field was dropped during implementation.

**There is no transparency about the model, because there is no model choice.** `const DEFAULT_MODEL: &str = "base.en"` (`crates/echo/src/stt/whisper.rs:12`) is effectively compile-time. `WhisperEngine::with_cache` is the only way past it and no production caller uses it. The Settings row that reads "Whisper · base.en" is not reporting what ran, it is reporting a constant. Meanwhile `resolve_engine` and `engine_summary` (`crates/echo/src/stt/mod.rs:19-36` and `:42-59`) are two hand-synced copies of the same decision, so the UI can already report an engine the recorder will not use.

**The blank-audio text is real, and the premise behind it is wrong.** Echo has never had blank-audio handling. Across all 22 commits there is no filter, no strip, no bracketed-token handling, and the `transcribe` body in `whisper.rs` is byte-identical to the day it was written. `[BLANK_AUDIO]` is generated by the Whisper model itself, learned from subtitle training data, and whisper.cpp prints it faithfully. The string appears exactly once in the whisper.cpp tree, inside a Python example that strips it. So nothing regressed in Echo. What changed for the user is most likely the model file, the model directory, or the whisper binary, since `model_file()` takes the first of three candidate filenames it finds (`crates/echo/src/stt/whisper.rs:54-64`) and any of the three lookups can silently change.

The fix is not the one the internet recommends. We built whisper.cpp at commit `45f1593` and measured it. `-sns` / `--suppress-nst`, the flag every blog post names, turned a clearly-marked `[BLANK_AUDIO]` into `I'm going to put the water in the pot.` on white noise, and into a fluent fabricated German sentence with `-l de`. It bans the bracket tokens, so the model emits the next most likely thing, which is prose. That is strictly worse for dictation: a bracketed marker is catchable, a plausible sentence typed into the user's document is not. `--suppress-regex` was worse still, collapsing into 70-plus-token repetition loops. `--vad` with a Silero model produced a genuinely empty result on every non-speech fixture, because the silent window never reaches the decoder at all.

**There is no CI.** No `.github` directory exists. And a CI job built from the README's install list fails, because `libdbus-1-dev` is missing from it and `libdbus-sys` panics without it. A second missing package, `libayatana-appindicator3-1`, is loaded by `dlopen` at runtime, so a user who follows the README exactly builds successfully and then has no tray.

Underneath four of these five sits one absence. **Echo has no persisted configuration.** Every setting is an environment variable read at its point of use, and `paths.rs` exposes only `data_dir`, `dictionary_path`, `history_path`, and `status_path`. There is no config file and no `XDG_CONFIG_HOME` resolver. That matters more than it sounds, because the GUI and the recorder are frequently different processes. The GUI's record button spawns a thread in-process, but a GNOME shortcut bound to `echo-desktop rec --toggle` spawns a fresh process that inherits the desktop session environment and can never see anything the GUI set. Microphone choice, model choice, and language choice are all just fields on a struct that does not exist yet. Applying **principle-foundational-thinking**, that struct is the scaffold and it lands before any picker UI.

## Scope

**Included**

- A GitHub Actions check workflow and a release workflow producing downloadable Linux artifacts.
- One icon source of truth, a generator that renders every size a Linux app needs, a tray-specific glyph, and correct wiring into the bundle, the tray, the desktop entry, and the favicon.
- A typed configuration store in `echo-core`, shared by the desktop process and the CLI process, with environment variables kept as overrides.
- A writable Settings view: microphone, engine, Whisper model, language, cleanup mode, HUD.
- Microphone enumeration and selection.
- Whisper switched to JSON output, so the model that actually loaded and the language that was actually used are read from the engine rather than assumed.
- Language selection across all 100 languages whisper.cpp supports, plus automatic detection.
- Blank-audio and non-speech hallucination handling, via VAD at the source and a residue filter at the engine boundary.
- A guided model download, since "supports 100 languages" is false while the default model is English-only.
- Fixing the sherpa-onnx stdout parse, which the investigation found is likely broken today.

**Excluded**

- Windows and macOS builds and bundles. The user asked for Linux only, and `bundle.targets: "all"` already resolves to deb, rpm, and AppImage on Linux.
- Streaming or partial transcription. The engine boundary stays "hand it a WAV, get text back".
- A background daemon. The one-shot CLI process is the design and a config file is enough to make it work; a daemon would be a much larger change for the same user-visible result (**principle-laziness-protocol**).
- Real-time audio level metering in the HUD. Phase 12 adds a one-shot level check for the mic picker only. Continuous metering needs the capture path off its mutex, which is a separate piece of work.
- Cleanup rules for non-English languages. Phase 17 stops the English rules from corrupting other languages; writing German or Japanese rules is out of scope.
- Migrating to whisper.cpp's new native `parakeet-cli`. Flagged in Alternatives as worth evaluating, not committed to.
- Changing the design language. Phases 11, 12, 15 and 18 add controls to the existing Settings view using the existing token system.

## Constraints

- **The frontend build is a hard prerequisite for every cargo command.** `tauri-build` resolves `frontendDist` at compile time, so `cargo check`, `cargo clippy`, `cargo test`, and `cargo build` all fail with a proc-macro panic if `frontend/dist` is absent. Every CI job and every phase's verification runs `npm run build --prefix frontend` first.
- **Two native packages are missing from the README.** `libdbus-1-dev` at build time, verified by reproducing the `libdbus-sys` panic. `libayatana-appindicator3-1` at runtime for the tray, verified by reading the loader's search list out of the release binary.
- Rust 1.88 or newer. The workspace declares `rust-version = "1.88"`, and Cargo 1.85 or newer is separately required to parse `edition2024` in a transitive dependency.
- Tauri 2.11.5, no plugins. All seven IPC commands are hand-written in `src-tauri/src/main.rs`, and `core:default` already permits `invoke`, so new commands need no capability change.
- **The GUI and the recorder are often separate processes.** Any setting must round-trip through the filesystem. Test the bound-shortcut path explicitly; a setting can appear to work through the GUI button and silently fail through the compositor shortcut.
- **Environment variables must keep winning.** Every existing test sets `ECHO_*`. Precedence is env, then config file, then default, so the suite keeps passing untouched.
- Tauri's PNG icons must be RGBA 32-bit. `tauri-codegen` panics with `icon ... is not RGBA` otherwise, which is exactly what `assets/icons/echo.png` would do if added to `bundle.icon`.
- `tauri-bundler` derives icon install paths from each PNG's own pixel dimensions and ignores non-PNG entries, so an SVG in `bundle.icon` can never reach a package.
- **`.en` Whisper models silently ignore `-l`.** whisper-cli resets `params.language = "en"`, prints a warning to stderr, and exits 0. It will produce confident English text from German speech. Echo must refuse rather than pass the flag through.
- Do not read `n_langs` to decide whether a model is multilingual. `base.en` prints `n_langs = 99`. The reliable signal is `model.multilingual` in the JSON output, or the `.en` filename suffix.
- Parakeet has no language flag and no detected-language readback. Its `lang` field comes back empty. That asymmetry with Whisper gets surfaced in the UI, not papered over.
- The existing JSON store pattern is the house style: a private file-wrapper struct, `serde_json`, `write_atomic`, and `set_aside_corrupt` on a parse failure rather than a hard error. See `crates/echo-core/src/dictionary.rs:28-69`.
- No `select` styling exists anywhere in `frontend/src/styles/`. An unstyled `<select>` renders as a raw platform widget in both themes.
- The health cache holds engine, injection, and microphone readiness for 10 seconds (`src-tauri/src/main.rs:45-65`). A settings write must invalidate it or the UI lags a change by up to 10 seconds and reads as a bug.

## Alternatives

Four decisions had real competing options (**principle-exhaust-the-design-space**).

**How settings reach the recorder process.**

1. Environment variables only, the status quo. Cannot work. A compositor-spawned process inherits the session environment, not the GUI's.
2. Extend the status file. Rejected. It is the one store with no serde, hand-parsed `key=value`, and its parser silently ignores lines it does not recognise. Putting settings in a parser that fails quietly is the wrong direction.
3. A background daemon owning state, with the CLI as a thin client. Rejected. It is a large change to the process model for the same result a file achieves.
4. **A JSON config file under `$XDG_CONFIG_HOME/echo/config.json`, chosen.** It matches the dictionary and history stores exactly, it is inspectable and editable by hand, and both processes already know how to resolve XDG paths.

**How to stop blank audio and hallucinated non-speech text.**

1. `-sns` / `--suppress-nst`. Rejected on measurement. It replaces a catchable marker with an uncatchable fabricated sentence.
2. `--suppress-regex`. Rejected on measurement. Degenerate repetition loops in every language tried.
3. `-nth` / `--no-speech-thold` alone. Insufficient. On digital silence it never fires, because the model is confidently emitting a real token so `no_speech_prob` stays below the threshold. Two upstream issues covering this are still open.
4. Output filtering alone. Insufficient alone, and it ships first anyway. A sweep across 27 languages and 4 non-speech fixtures found that roughly half the failures are unbracketed prose: `TV GELDERLAND 2020.` in Dutch on all four fixtures, a fake Russian subtitle-editor credit, `you` in English. No pattern catches those.
5. **`--vad` with a Silero model, plus a residue filter, chosen.** VAD attacks the root cause; the decoder never sees the silence. Filtering stays as a backstop for what leaks past, and it ships in phase 4 because it needs no new download.

**Icon production.**

1. Hand-exported PNGs committed alongside the SVG. Rejected. That is how the repo reached three files in three colour schemes.
2. Run `tauri icon` once and commit the output. Rejected. It cannot produce a distinct tray glyph, and re-running after an art change is a manual step nobody will remember.
3. **SVG masters plus a checked-in generator script, with a CI drift check, chosen** (**principle-build-the-lever**). The generator is the artifact a reviewer reruns, and CI failing on drift is what keeps the sources and the rasters honest.

**The path to multilingual dictation.**

1. Parakeet TDT 0.6B v3. 25 European languages with automatic identification, no way to pin one, and an empty `lang` field so Echo cannot display what it detected.
2. **Whisper multilingual, chosen as the language-capable path.** 100 languages, pinnable, `-l auto` for detection, and `result.language` in the JSON so the UI can show what was actually used.
3. whisper.cpp's native `parakeet-cli`, with GGML weights at `ggml-org/parakeet-GGUF`. It would let Echo drop sherpa-onnx and the ONNX runtime entirely and ship one binary family with one model format. Genuinely attractive and deliberately not in this plan. It is new, no accuracy comparison against sherpa-onnx exists, and committing to it before measuring would be the kind of bet this plan should not make. Evaluate after phase 19.

Both engines stay. Parakeet keeps its place as the fast automatic option and gets its stdout parse fixed; Whisper becomes the option you choose when you want control.

- **control-cli** (from `cursor-team-kit`) for every phase touching `echo-desktop rec --once|--toggle|--hold`.

- **unslop** over every prose surface. **deslop** (`/deslop`) over each diff before commit. **no-comments** (`/no-comments`) before review.

## Verification

Project-level commands, run per phase and at completion. The frontend build is first because every cargo command depends on it:

```sh
npm ci --prefix frontend
npm run build --prefix frontend
npm run test --prefix frontend
npm run lint --prefix frontend
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo build --release
```

From phase 1 onward, CI runs exactly this list, so a green PR is the project-level check.

Two surfaces have no control skill and the gap is real. The X11 HUD is raw `x11rb`; verify it with `echo-desktop --hud-demo` under Xvfb plus a screenshot, the fallback [02-design-overhaul/testing.md](../02-design-overhaul/testing.md) already established. The GTK tray is drawn by libappindicator into the desktop panel and cannot be driven at all; phase 6 verifies it by screenshotting a real panel at 22 px and 24 px.

## Implementation guidance

- Branches follow `cursor/<descriptive-name>-5c82`. One phase per PR, in order.
- Each phase is independently shippable. The app must be coherent after every merge; no phase may leave a control visible that does nothing.
- Apply **how** before touching an unfamiliar file, `/deslop` before each commit, **unslop** on PR prose, and Cursor's built-in **babysit** skill after opening each PR.
- **Do not carry compatibility shims between phases** (**principle-migrate-callers-then-delete-legacy-apis**). Phase 8 migrates every environment reader and deletes the old direct reads in the same diff. Phase 13 deletes the `.txt` sidecar path in the same diff that adds JSON parsing.
- **Redesign holistically, deliver incrementally** (**principle-redesign-from-first-principles**). If Echo had been built with a config file on day one, `resolve_engine` and `engine_summary` would never have been two functions, `AudioCapture` would have kept its `device` field, and `DEFAULT_MODEL` would not exist. Each phase moves toward that shape rather than layering onto the current one.
- **Collapse duplicated decisions rather than teaching both copies a new trick.** Four pairs are hand-synced today: `resolve_engine`/`engine_summary`, `from_env`/`mode_name`, `hud_disabled`/`enabled`, and the two `default_input_device` lookups. Every one of them is a place where a settings change can make the UI lie about what the recorder will do.
- No new dependencies without naming the alternative that was rejected. The only ones this plan anticipates are a resvg-based rasterizer for the icon generator (phase 5) and nothing else. `serde_json` is already present for the config store and the JSON engine output.
- Attach evidence to every PR. Screenshots at 920x680 in both themes for UI phases, terminal transcripts for CLI phases, and the actual downloaded artifact for phase 2.
